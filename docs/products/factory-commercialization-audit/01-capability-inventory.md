## Two structural facts that change the reuse math

1. **The entire HL-BOS backend is already deployed to production — at the database layer.**
   Verified live: **18 business schemas, ~130 tables**: `identity(8) · platform(1) ·
audit(2) · events(4) · entitlements(4) · workflows(3) · billing(8) · storage_meta(1) ·
comms(7) · integrations(5) · ai(7) · discovery(19) · provisioning(7) · sales(7) ·
visibility(8) · bti(14) · hlvs(19) · graph(6)`. There is **no customer data**, but the
   schema, RLS, functions and public RPCs are live. Reuse is not theoretical — it is applied.
2. **Runtime and UI are built but NOT deployed.** 8 edge functions exist in `supabase/functions`
   (`ai-gateway, billing-webhook, commerce-worker, discovery-website-worker,
discovery-blueprint-worker, events-dispatcher, hlvs-factory-worker`, + `_shared`) — all
   built/tested, **0 deployed**. 4 apps exist (`control-center, executive-portal, hl-bti,
hl-bti-alpha`) — only control-center runs (locally). So the gap to revenue is **deploy +
   ignite + commercial terms**, not construction.

## Maturity legend

- **Live-on-prod** — schema/functions applied to production (may still need runtime deploy to be _usable_).
- **Built-undeployed** — code + tests exist; runtime not turned on.
- **Mock-only** — engine real but runs on mock providers / no live egress.
- **Absent** — does not exist as a shared asset (flagged honestly).

## Reuse dividend (the whole point)

- **9-module COMMON_SPINE** underpins all 8 composed products — identity, tenancy, audit,
  events, entitlements, workflows, billing-core, storage, comms. Building any new product
  starts at ~9 modules already done.
- **19 `MODULE_REGISTRY` modules**, all `live` or `built_undeployed` — none unbuilt.
- **27 canonical capabilities**, of which ~15 are `implemented`, ~7 `partial`
  (runtime-not-on), ~5 `planned` (need a net-new engine: `ai_receptionist`, `scheduling`,
  `route_assessment`, `event_management`, `document_extraction`).
- **The differentiator between products is deployment + a small amount of product-surface
  assembly — not platform construction.**

## Honest gaps (name them, per the honesty rule)

- **No shared UI library** — acceptable today (one app shipping); revisit when a second app launches.
- **No standalone CRM** — reuse discovery + identity; do **not** build a CRM service.
- **Billing Stripe adapter is a 501 stub** — the one shared service that must be finished before self-serve subscriptions (out-of-band billing avoids it for a first launch).
- **Live web egress (SSRF guard)** for Website Analysis is unbuilt — gates VisibilityAI touching real sites.
- **Nothing at the runtime/app layer is deployed** — the universal blocker is ignition, not code.
