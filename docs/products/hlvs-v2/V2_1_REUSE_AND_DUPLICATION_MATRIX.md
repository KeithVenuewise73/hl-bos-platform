# HLVS V2 · V2-1 — Reuse & Duplication Matrix (Step 0)

**For:** Keith Herman, CEO · **Author:** Claude · **Date:** 2026-08-01 · **Branch:** `claude/hlvs-v2-foundation`
**Rule:** _ASSEMBLE. DO NOT REBUILD._ No `vstudio` table is created if an existing canonical object can satisfy the requirement safely.
**Evidence:** live HL-BOS Core (`mvvtngiopdrgiedjmhfb`) schema inventory + `@hl-bos/catalog` source, both read this session.

## Outcome

The architecture proposed 9 `vstudio` tables. This audit reduces the net-new surface to **6 tables**. Three proposed tables are **not built** — they are satisfied by reuse or on-demand computation:

- `sources` → **in-code constant** (V2-1 has no connectors; nothing to persist yet).
- `reuse_analyses` → **computed on-demand** from `@hl-bos/catalog` (deterministic; snapshot stored inside a recommendation when one is generated).
- `portfolio_impacts` / `factory_handoffs` → **computed on-demand** from catalog + graph; V2-1 Factory readiness is a **read-only preview**, so no handoff row is written.

## Net-new `vstudio` tables (6) — each justified above

`opportunities` · `evidence` · `notes` · `evaluations` · `recommendations` · `decisions`

## Deferred (built later, not V2-1)

`sources` (connectors arrive in V2-2) · stored `reuse_analyses` / `portfolio_impacts` / `factory_handoffs` (V2-1 computes these on demand; persistence only when it earns its keep).

**Conclusion:** the foundation adds one thin 6-table schema and reuses identity, tenancy, ai, events, workflows, audit, graph, storage, and the entire `@hl-bos/catalog` reuse engine unchanged. No canonical capability is duplicated.
