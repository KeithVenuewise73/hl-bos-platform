# Venuewise Backend Harvest · 01 — Complete Capability Inventory

**READ-ONLY harvest.** Every functional capability discovered in the Venuewise backend
(`urwnbskrtoplgnkkxuvl`), grouped logically. Fields per capability: **Business Purpose ·
Primary Product · Status · Dependencies · Current Workflow · Classification.** (Supporting DB
objects → [02](02-capability-to-database-map.md); commercialization + maturity → [03](03-commercialization-and-maturity.md).)

**Status** = Production (live data + in use) · Functional (fully built, little/no data) ·
Partial · Prototype · Unused. **Classification** = Shared Factory Module · Sports Vertical
Module · Venuewise-specific · Internal Only · Retired · Investigate.

## Cross-cutting observations

- **Security posture:** RLS on **every** table; the write/read path is almost entirely
  **SECURITY DEFINER** RPCs gated by helper predicates (`current_*`, `is_admin`,
  `is_media_member`, `wf_has_role`) — a consistent, centralized authorization model.
- **Automation:** 5 `pg_cron` jobs + `pg_net` async HTTP drive the SMS outbox, calendar
  refresh, schedule sync, nightly reminders, and status refresh — the platform runs itself.
- **The platform genuinely operates:** live data in identity, family, calendar, SMS
  (284 sent), analytics (703 views), subscriptions, and workflow events (52).
